# Agent Flows

Formulários do WhatsApp de várias telas que um agent de IA pode entregar a um cliente no meio de uma conversa. O agent decide quando pedir informações estruturadas — nome, datas, uma foto de documento, um questionário de várias etapas — e o seu cliente preenche tudo em um formulário nativo do WhatsApp, em vez de uma longa troca de mensagens.

## Quando usar o Agent Flows

Use um flow quando o chat sozinho não for o formato certo para a pergunta:

- **Captura de leads** — nome + e-mail + porte da empresa + preferência de reunião, tudo em uma tela que o cliente preenche de uma só vez
- **Agendamento de horários** — escolher uma data, escolher um horário, confirmar
- **Envio de documentos ou fotos** — coletar um documento, um recibo, a foto de um produto danificado
- **Triagem de várias etapas** — listas de sintomas, formulários de inscrição, pesquisas
- **Perguntas condicionais** — perguntar "que tipo de animal de estimação?" somente se a pessoa responder sim a "você tem um animal de estimação?"

O agent recomenda um flow quando o prompt de sistema dele + o contexto da conversa coincidem. Você configura o flow uma única vez no painel de administração; o agent o reutiliza em todas as conversas.

## Criar um flow

Os flows ficam em **Agent Flows** no painel de administração do cliente. Cada flow tem:

- Um **nome e uma descrição** que o agent lê para decidir quando usá-lo
- Uma ou mais **telas**, cada uma com **componentes** (campos)
- **Lógica de tela** opcional (ramificar para telas diferentes conforme o que o cliente escolher)
- **Variantes A/B** opcionais — divide o tráfego entre duas versões do mesmo flow
- **Publicações** por idioma no WhatsApp (traduza uma vez, publique por idioma)

## Começar a partir de um modelo

Você não precisa começar com um editor em branco. Abra a aba **Modelos** na lista de Agent Flows para explorar uma biblioteca curada de flows prontos para usar: captação de leads, agendamento de demos, recepção de suporte, opiniões de produto e muito mais. Clique em **Usar este modelo** e ele cria um rascunho editável no seu próprio workspace: as telas, os campos, a lógica e as traduções vêm preenchidos. Vincule o rascunho a um número do WhatsApp, ajuste o que quiser e publique.

Um modelo é só um ponto de partida: depois que você cria sua cópia, ela é um flow normal que pertence totalmente a você e que você pode editar à vontade. A biblioteca de modelos está disponível em todos os planos que incluem Agent Flows.

## Biblioteca de componentes — 23 variantes

O menu **Add field** do editor agrupa os 23 componentes em sete categorias. Escolha o formato certo para os dados de que você precisa.

### Display (exibição, sem entrada)

Estes mostram texto ou imagens na tela sem pedir nenhuma entrada do cliente.

| Componente | Use para |
|-----------|-----------|
| **Text Heading** | Um título grande no topo de uma tela (≤ 80 caracteres) |
| **Text Subheading** | Um título secundário abaixo do título principal (≤ 80 caracteres) |
| **Text Body** | Um parágrafo de texto explicativo. Aceita **negrito** e ~~tachado~~ (≤ 4096 caracteres) |
| **Text Caption** | Texto de apoio curto; markdown permitido (≤ 4096 caracteres) |
| **Rich Text** | Um bloco markdown — útil para termos, avisos legais, instruções formatadas |
| **Image** | Uma única imagem (≤ 100 KB) |
| **Image Carousel** | Até 10 imagens deslizáveis com legendas — galerias de produtos, antes/depois, instruções |

### Inputs (texto de uma e de várias linhas)

| Componente | Use para |
|-----------|-----------|
| **Text Input** | Uma caixa de texto de uma linha — nome, e-mail, respostas curtas |
| **Text Area** | Uma caixa de texto de várias linhas — comentários, descrições, respostas mais longas (≤ 600 caracteres) |
| **Embedded Link** | Um link embutido para tocar e abrir, com texto personalizado (≤ 25 caracteres) |

### Choices (escolher de um conjunto)

| Componente | Use para |
|-----------|-----------|
| **Dropdown** | Escolher um item de uma lista longa (mais de 10 opções) |
| **Radio Buttons** | Escolher um item de uma lista curta (≤ 5 opções), todas visíveis ao mesmo tempo |
| **Checkboxes** | Escolher qualquer quantidade de itens de uma lista, com mínimo e máximo opcionais |
| **Chips Selector** | Escolher entre até 20 chips no estilo etiqueta — interesses, categorias, seleção múltipla ocupando pouco espaço |

### Data e hora

| Componente | Use para |
|-----------|-----------|
| **Date Picker** | Uma única data — data de reserva, data de nascimento |
| **Calendar Picker** | Uma superfície de calendário com intervalo de datas opcional, limites mínimo/máximo e datas indisponíveis esmaecidas — agendamento de horários, estadias em hotel |

<Callout type="info">
  Tanto o `Date Picker` quanto o `Calendar Picker` são mantidos como componentes distintos. Use o **Date Picker** para uma única data rápida; use o **Calendar Picker** quando precisar de uma grade de mês visível, de um intervalo ou de esmaecer datas específicas.
</Callout>

### Envios de arquivos

| Componente | Use para |
|-----------|-----------|
| **Photo Picker** | O cliente envia fotos da câmera ou da galeria (até 30 por envio) |
| **Document Picker** | O cliente envia documentos — PDF, DOC, etc. (até 10 por envio) |

<Callout type="warning">
  **Exclusão mútua:** Uma única tela pode conter um Photo Picker **ou** um Document Picker, mas não os dois. Coloque-os em telas separadas se o seu flow precisar dos dois tipos de envio.
</Callout>

### Layout

| Componente | Use para |
|-----------|-----------|
| **Navigation List** | Até 20 linhas tocáveis com chevrons — escolher uma categoria, escolher um produto, escolher uma tela de destino |
| **Opt-In** | Uma caixa de consentimento — termos de serviço, consentimento de marketing, consentimento da LGPD/GDPR |
| **Footer** | O elemento de envio na última tela do flow |

### Logic (renderização condicional)

| Componente | Use para |
|-----------|-----------|
| **If** | Renderizar alguns componentes apenas quando uma condição for verdadeira (`then`) — opcionalmente com uma alternativa (`else`) |
| **Switch** | Renderizar componentes diferentes conforme um valor que o cliente escolheu antes (vários `cases` + um `default` opcional) |

<Callout type="info">
  **If** e **Switch** aceitam até **3 níveis de aninhamento**. Se você perceber que está aninhando mais fundo do que isso, divida a lógica em várias telas com roteamento no nível da tela.
</Callout>

## Flows de várias telas e roteamento

Um flow pode ter até **10 telas**. Cada tela termina com um **Footer** que envia o flow ou avança para a próxima tela. Use o editor de **lógica de tela** para encaminhar o cliente a uma próxima tela diferente conforme o que ele escolheu — por exemplo, clientes que selecionam "Reembolso" vão para uma segunda tela específica de reembolsos; todos os demais vão para a tela de acompanhamento genérica.

Para renderização condicional no nível do componente dentro de uma única tela, use **If** / **Switch**.

## Localização

Os flows são publicados por idioma. Traduza o flow uma vez e escolha os idiomas em que você publica a partir da **lista completa de idiomas com suporte do WhatsApp** — todos os idiomas em que a Meta permite publicar um WhatsApp Flow. O seletor mostra opções distintas por região quando isso importa, então você pode publicar **Português (Brasil)** separadamente de **Português (Portugal)**, ou **中文 (简体)** separadamente de **中文 (繁體)**. Cada cliente vê a versão que corresponde ao idioma do WhatsApp dele; se o idioma de um cliente não estiver publicado, o idioma padrão da integração é usado como fallback. (Quando o cliente escreve em um idioma base, como português, e você publicou apenas uma variante regional, como o português do Brasil, ele ainda recebe o formulário localizado.)

## Testes A/B

Se você quiser testar duas versões de um flow entre si, configure-as como **variantes** na aba Variants. Os clientes são divididos de forma determinística (o mesmo cliente sempre vê a mesma variante); a visão **Submissions** mostra de qual variante veio cada envio, e o **Field Heatmap** permite comparar as taxas de abandono e de conclusão lado a lado.

## Geração por IA

Se você tem um plano de nível superior, o editor oferece **geração de formulários por IA**: escreva um prompt de uma linha ("um formulário de reserva de hotel com intervalo de datas e envio de foto"), ou envie um PDF / imagem de um formulário existente, e o assistente redige o flow para você. O rascunho é totalmente editável — cada campo é reversível no editor (sem instantâneos opacos de IA).

## Envios e análises

Depois que um flow é publicado, cada envio chega à visão **Submissions** desse flow. Cada linha mostra:

- Quem enviou, quando e por meio de qual agent
- Os valores completos dos campos do formulário
- Uma **pontuação de IA** (0–100) que o assistente atribuiu ao envio — os leads de maior valor sobem para o topo
- Os turnos de chat da conversa **logo antes** de o formulário ser aberto (a junção com o contexto da conversa — para ver por que o agent decidiu pedir este envio)

As análises agregadas incluem uma **faixa de KPIs** (iniciados / concluídos / taxa de abandono), um **Field-Level Heatmap** que mostra onde os clientes desistem e um **Narrative Diagnostic** — um analista de IA a quem você pode perguntar "por que as pessoas estão desistindo na tela 2?" e que rastreia a resposta pelo mapa de calor, pelos envios e pelo contexto da conversa.

## Notificações e o funil de leads

Um envio só vale se alguém agir rápido. A aba **Distribuir** de cada fluxo tem um bloco de notificações para que as pessoas certas fiquem sabendo de um lead assim que ele chega:

- **Notificações de envio** — quando um formulário é enviado, aparece uma notificação no app, com link direto para aquele envio. Você ativa por fluxo.
- **Notificações de resposta após assumir o atendimento** — quando alguém da sua equipe responde a um lead no WhatsApp e o cliente escreve de volta, você recebe uma segunda notificação — o segundo tempo do ciclo de velocidade de resposta.
- **Destinatários de e-mail** — adicione até dez endereços de e-mail e cada envio também dispara um e-mail diferido com link para o envio, para que a equipe offline não perca o lead.

Um cliente tagarela não vai te encher de notificações: uma rajada de mensagens logo após um envio é agrupada em **uma única** notificação, e uma nova só dispara depois que um humano de fato respondeu e o cliente volta a escrever.

Cada fluxo também tem uma **faixa de funil** na sua página de envios — uma visão somente leitura para ver num relance em que ponto os leads estão:

| Etapa | Significado |
|-------|-------------|
| **Enviado** | todos os envios do fluxo |
| **Atendido pela IA** | o agente deu sequência à conversa depois do formulário |
| **Respondido por humano** | alguém da sua equipe respondeu manualmente |
| **Resolvido** | a conversa foi arquivada |
| **Aguardando resposta humana** | notificado, mas nenhum humano respondeu ainda — seus leads em risco |

O funil é uma **visão heurística** para gerenciar o pipeline num relance, não um modelo de atribuição de receita.

## Confirmações contextuais

Quando um cliente termina um formulário, ele vê a tela de conclusão instantânea do WhatsApp com a mensagem de confirmação que você configurou. Logo depois, o agente também envia uma **mensagem de WhatsApp separada que faz referência ao que o cliente realmente preencheu** —"Pronto, agendei você para terça às 14h. Mais alguma coisa?"— para que a conversa continue de forma natural em vez de deixar o cliente diante de um "obrigado" estático. O agente já conhece os valores enviados, então a confirmação é específica, não genérica.

Isso vem **ativado por padrão** em cada formulário. Se você preferir que o agente fique em silêncio após um envio, desative **Confirmar envios** na aba **Distribuir** do formulário. A confirmação também fica em silêncio automaticamente quando alguém da sua equipe assume a conversa: você não vai receber uma mensagem de IA atropelando uma resposta humana.

## Compartilhar um formulário como link de campanha

Formulários publicados não vivem só dentro das conversas que o agente inicia. Abra o card **Recurso de campanha** na aba **Distribuir** do formulário e gere um **link compartilhável** — um link padrão de conversa direta do WhatsApp (mais um **QR code** para baixar) que você pode colocar em um e-mail, na bio do Instagram, em um botão "Agendar uma demo" ou imprimir em um panfleto.

Quando alguém clica no link, o WhatsApp abre uma conversa com o seu número e uma mensagem já preenchida; o usuário toca em enviar e **o formulário exato abre como a primeira resposta**, sem adivinhação nem saudação da IA no meio. Quem clicou em "Agendar demo" recebe o formulário de agendamento na hora. Depois, o agente cuida do resto da conversa normalmente.

Cada link tem um **contador de aberturas** para você ver quantas pessoas abriram o formulário por ele, e você pode **revogar** um link a qualquer momento. Se o texto de um link for editado ou removido antes do envio, ou se o link for revogado, a mensagem simplesmente segue para uma conversa de IA normal — nada quebra.
