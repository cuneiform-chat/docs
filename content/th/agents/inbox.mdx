# Inbox และ Human Handoff

เมื่อ AI agent ของคุณไม่สามารถแก้ไขการสนทนาได้อย่างสมบูรณ์ มันสามารถส่งต่อผู้ใช้ให้กับสมาชิกในทีม สิ่งนี้เรียกว่า Human Handoff — เชื่อมต่อ AI support กับคนจริงเมื่อจำเป็นที่สุด

import { Callout } from 'nextra/components'

## ภาพรวม

Human Handoff มีให้:
- การส่งต่อที่ราบรื่นจาก AI agent ไปยังสมาชิกในทีม
- แชท real-time กับผู้ใช้บน channel ที่เชื่อมต่อ
- การจัดการ queue พร้อมการติดตามสถานะ
- การแจ้งเตือน in-app และ email เมื่อผู้ใช้ขอความช่วยเหลือ
- หมดอายุอัตโนมัติถ้าไม่มี agent ว่างภายในเวลาที่ตั้งค่า

## ข้อกำหนดเบื้องต้น

- AI agent ที่ Active พร้อมเปิดใช้งาน Human Handoff
- อย่างน้อยหนึ่ง channel ที่เชื่อมต่อ (หรือ Website Widget)
- สมาชิกในทีมที่พร้อมตอบใน admin panel

## การเปิดใช้งาน Human Handoff

Human Handoff ตั้งค่าต่อ agent

1. ไปที่ **Agents** แล้วคลิก agent ของคุณเพื่อแก้ไข
2. ใน **Configuration** tab เลื่อนไปที่ส่วน **Human Handoff**
3. เปิด toggle **Enable Human Handoff**
4. ตั้งค่าการตั้งค่า:

| การตั้งค่า | คำอธิบาย | ค่าเริ่มต้น |
|-----------|----------|-----------|
| **Handoff Message** | แสดงให้ผู้ใช้เห็นเมื่อเริ่มการส่งต่อ | "I'm connecting you with a human agent. Please hold on." |
| **Accept Message** | ส่งอัตโนมัติเมื่อสมาชิกในทีมรับแชท | "Hi! I'm {'{agent_name}'} from {'{org_name}'}. How can I help you?" |
| **Resolve Message** | แสดงให้ผู้ใช้เห็นเมื่อแชทจบ | "You're now back with the AI assistant. How can I help?" |
| **Max Wait Time** | หมดอายุอัตโนมัติถ้าไม่มีใครรับ (5, 15, 30, 60 หรือ 120 นาที) | 30 นาที |

5. คลิก **Save Changes**

<Callout type="info">
  ข้อความรองรับ placeholder `{'{agent_name}'}` และ `{'{org_name}'}` ที่จะถูกแทนที่ด้วยค่าจริงโดยอัตโนมัติ
</Callout>

ดูรายละเอียดเพิ่มเติมเกี่ยวกับการตั้งค่า agent ได้ที่ [Configuration Options](/agents/configuring#human-handoff)

## วิธีการทำงาน

```
User asks to speak with a human
  → AI agent detects the request
  → Handoff message shown to the user
  → Session appears in the Inbox queue (status: Queued)
  → Team members receive in-app notification
  → If no response in 3 min, email reminder sent
  → Team member opens Inbox and clicks Accept
  → Accept message sent to the user
  → Real-time chat between user and team member
  → Team member clicks Resolve when done
  → Resolve message sent to the user
  → AI agent resumes the conversation
```

ระหว่าง handoff AI agent จะหยุดพัก ข้อความทั้งหมดจากผู้ใช้จะถูกส่งตรงไปยังสมาชิกในทีม เมื่อ resolve แล้ว AI agent จะกลับมาจัดการการสนทนาโดยอัตโนมัติ

## การใช้งานหน้า Inbox

ไปที่ **Inbox** ใน sidebar เพื่อดู handoff queue

### สถิติ Queue

ที่ด้านบนของหน้า คุณจะเห็น:

- **Queued** — จำนวนผู้ใช้ที่รอสมาชิกในทีม
- **Active** — จำนวนแชทที่กำลังดำเนินการ
- **Agents online** — จำนวนสมาชิกในทีมที่เปิดหน้า Inbox อยู่

<Callout type="info">
  สถานะ online ของคุณจะถูกติดตามอัตโนมัติขณะที่คุณเปิดหน้า Inbox ไม่ต้องกด "go online" ด้วยตนเอง
</Callout>

### การกรอง

ใช้ dropdown กรองสถานะเพื่อดู session เฉพาะ:

| ตัวกรอง | แสดง |
|---------|------|
| Queued & Active | การสนทนาที่ต้องการความสนใจ (ค่าเริ่มต้น) |
| Queued Only | ผู้ใช้ที่รอคนรับ |
| Active Only | การสนทนาที่กำลังดำเนินการ |
| Resolved | การสนทนาที่เสร็จแล้ว |
| Expired | Session ที่หมดเวลา |
| All | ทั้งหมด |

### Queue Table

แต่ละแถวแสดง AI agent ที่ escalate, channel ของผู้ใช้, สถานะ session, เหตุผลการ escalation, เวลารอ และสมาชิกในทีมที่ได้รับมอบหมาย (ถ้ามี)

คลิกแถวใดก็ได้เพื่อเปิดหน้ารายละเอียดแชท

## การรับและแชท

เมื่อคุณคลิก session ที่ queued หน้ารายละเอียดแชทจะเปิดขึ้น

### การรับ Session

คลิกปุ่ม **Accept** สีเขียวใน header สิ่งนี้จะ:

1. เปลี่ยนสถานะ session จาก Queued เป็น Active
2. ส่ง accept message ให้ผู้ใช้บน channel ของพวกเขา
3. เปิด message input เพื่อให้คุณเริ่มแชทได้

<Callout type="warning">
  สมาชิกในทีมเพียงคนเดียวเท่านั้นที่สามารถรับ session ได้ เมื่อรับแล้ว session จะถูกมอบหมายให้คุณ
</Callout>

### Chat Interface

หน้ารายละเอียดแชทมีสองส่วน:

**Chat Panel (ซ้าย):**
- ข้อความถูกจัดกลุ่มตามผู้ส่งพร้อม styling ที่แตกต่างกัน:
  - **User messages** (เข้ม) — ด้านซ้าย
  - **AI bot messages** (อ่อน) — ด้านขวา
  - **Human agent messages** (น้ำเงิน) — ด้านขวา, แสดงชื่อของคุณ
- พิมพ์ในช่องข้อความด้านล่างแล้วกด Enter เพื่อส่ง
- ข้อความจะถูกส่ง real-time ไปยัง channel ของผู้ใช้

**Context Sidebar (ขวา, เฉพาะ desktop):**
- **Timeline** — เวลาที่สร้าง, รับ, Resolve พร้อม live wait timer
- **Session** — สถานะ, channel, จำนวนข้อความ, agent ที่ได้รับมอบหมาย
- **Participants** — End user, AI agent และ human agent
- **Escalation Reason** — เหตุผลที่ AI ตัดสินใจส่งต่อ (ถ้ามี)

## การ Resolve Session

เมื่อคุณแก้ไขปัญหาของผู้ใช้แล้ว:

1. คลิกปุ่ม **Resolve** ใน header
2. Confirmation dialog จะปรากฏ
3. เพิ่ม **internal note** ได้ตามต้องการ (ไม่แสดงให้ผู้ใช้เห็น — สำหรับบันทึกของทีมคุณ)
4. คลิก **Resolve** เพื่อยืนยัน

หลังจาก resolve:
- Resolve message จะถูกส่งให้ผู้ใช้
- การสนทนากลับไปที่ AI agent
- Session เปลี่ยนเป็นสถานะ Resolved

## เมื่อไม่มีใครว่าง

ถ้าไม่มีสมาชิกในทีมรับภายใน **Max Wait Time** ที่ตั้งค่า:

1. สถานะ session เปลี่ยนเป็น **Expired**
2. ผู้ใช้ได้รับข้อความว่าไม่มี agent ว่าง
3. การสนทนากลับไปที่ AI agent โดยอัตโนมัติ

<Callout type="important">
  ตั้ง Max Wait Time ตามความพร้อมของทีม ถ้าคุณมีพนักงานจำกัด เวลาที่สั้นกว่า (5–10 นาที) ดีกว่าการปล่อยให้ผู้ใช้รอนาน
</Callout>

## การแจ้งเตือน

### การแจ้งเตือน In-App

เมื่อผู้ใช้ขอ human agent สมาชิกทุกคนในองค์กรของคุณจะได้รับการแจ้งเตือน in-app ผ่านกระดิ่งแจ้งเตือนใน header ของ admin panel

### Email Reminders

ถ้า handoff session อยู่ใน queue นาน **3 นาที** โดยไม่มีใครรับ email reminder จะถูกส่งให้สมาชิกทุกคนในองค์กรของคุณ สิ่งนี้ทำให้มั่นใจว่ามีคนได้รับแจ้งแม้ไม่ได้อยู่ใน admin panel

## Channel ที่รองรับ

Human Handoff ทำงานกับทุก channel ที่เชื่อมต่อ:

| Channel | วิธีการส่ง |
|---------|----------|
| Telegram | ส่งข้อความผ่าน bot |
| Discord | ส่งข้อความไปยัง channel |
| Slack | ส่งข้อความไปยัง channel |
| WhatsApp | ส่งข้อความผ่าน API |
| Meta (Facebook Messenger) | ส่งข้อความผ่าน page |
| Google Chat | ส่งข้อความไปยัง space |
| Website Widget | ข้อความปรากฏใน chat widget |

<Callout type="info">
  บน Website Widget ข้อความจะถูกส่งผ่าน real-time streaming บน channel อื่นๆ ทั้งหมด ข้อความจะถูก push ผ่าน API ของ channel โดยตรง
</Callout>

## FAQ

### Human Handoff มีใน plan ใดบ้าง?

Human Handoff มีให้ในทุก plan รวมถึง Trial เปิดใช้งานต่อ agent ใน Configuration tab

### สมาชิกหลายคนสามารถจัดการ handoff ได้หรือไม่?

ได้ สมาชิกทุกคนในองค์กรของคุณสามารถรับ session ที่ queued ได้ ตัวนับ "Agents online" แสดงจำนวนสมาชิกที่เปิดหน้า Inbox อยู่

### ถ้าฉันปิด browser ระหว่างแชทที่ active อยู่?

Session ยังคงอยู่ในสถานะ Active เมื่อคุณกลับมาที่หน้า Inbox คุณสามารถสนทนาต่อจากจุดที่ค้างไว้ได้

### ผู้ใช้รู้ได้อย่างไรว่ากำลังคุยกับคน?

ผู้ใช้จะได้รับ accept message ที่ตั้งค่าไว้เมื่อคุณเข้าร่วม นอกเหนือจากนั้น ประสบการณ์ขึ้นอยู่กับวิธีที่คุณเขียน handoff message และสไตล์การสนทนาของคุณ

### AI เห็นข้อความของ human agent หรือไม่?

ข้อความของ human agent จะถูกเก็บไว้ใน conversation history เมื่อ AI กลับมาหลัง resolve มันจะมี context จากการสนทนา handoff

### ฉันสามารถดู handoff session ที่ผ่านมาได้หรือไม่?

ได้ ใช้ตัวกรองสถานะในหน้า Inbox เพื่อดู session ที่ **Resolved** หรือ **Expired** คลิกที่ session ใดก็ได้เพื่อดูการสนทนาทั้งหมด

### อะไรกระตุ้นให้ AI ส่งต่อ?

AI agent ตัดสินใจ escalate เมื่อผู้ใช้ขอพูดคุยกับคนอย่างชัดเจน (เช่น "ขอคุยกับคนจริงได้ไหม?") AI ใช้การตรวจสอบแบบ classification เพื่อยืนยันว่าผู้ใช้ต้องการคนจริงก่อนสร้าง handoff
