# Website Crawling

import { Callout } from 'nextra/components'

Crawl เว็บไซต์สาธารณะและเพิ่มเนื้อหาเข้าสู่ Content ของคุณ Crawler จะเยี่ยมชมหน้าเว็บ ดึงเนื้อหาเป็น Markdown และให้คุณตรวจสอบและแก้ไขก่อนประมวลผล

## การเข้าถึง

ไปที่ **Content** ในเมนู sidebar จากนั้นคลิกแท็บ **Website**

## วิธี Crawl เว็บไซต์

### ขั้นตอนที่ 1: ใส่ URL

วาง URL เว็บไซต์ในช่องกรอก (เช่น `https://docs.example.com`) Crawler จะเริ่มจากหน้านี้และติดตาม link เพื่อค้นพบหน้าเพิ่มเติม

### ขั้นตอนที่ 2: ตั้งค่าตัวเลือก

| ตัวเลือก | ค่าเริ่มต้น | คำอธิบาย |
|----------|------------|----------|
| Target Folder | ไม่มีโฟลเดอร์ (root) | เลือกโฟลเดอร์ปลายทางสำหรับเอกสารที่ crawl |
| Single page only | ปิด | Crawl เฉพาะ URL ที่ใส่ ไม่ติดตาม link |
| Respect robots.txt | เปิด | ปฏิบัติตามกฎ robots.txt ของเว็บไซต์ |

### ขั้นตอนที่ 3: เริ่ม Crawl

คลิก **Crawl** เพื่อเริ่มต้น Crawler จะเยี่ยมชมหน้าเว็บเริ่มจาก URL ของคุณและดึงเนื้อหา

### ขั้นตอนที่ 4: ดูความคืบหน้า

- แถบความคืบหน้าแสดงจำนวนหน้าที่ crawl เทียบกับจำนวนสูงสุดของ plan
- หน้าเว็บจะปรากฏในรายการแบบสดขณะถูกค้นพบ
- คลิกหน้าใดก็ได้เพื่อดูตัวอย่างเนื้อหาทันที
- ใช้ปุ่ม **Cancel** เพื่อหยุด crawl ได้ตลอดเวลา

<Callout type="info">
  สามารถ crawl ได้ทีละครั้งต่อองค์กร รอให้ crawl ปัจจุบันเสร็จสิ้นหรือยกเลิกก่อนเริ่มใหม่
</Callout>

## การตรวจสอบหน้าที่ Crawl

หลังจาก crawl เสร็จสิ้น คุณสามารถตรวจสอบและแก้ไขหน้าก่อนเพิ่มเข้าสู่ Content

### แก้ไขเนื้อหาหน้า

1. คลิกหน้าใดก็ได้ในรายการเพื่อเปิด editor
2. แก้ไข **title** และ **markdown content**
3. ลบส่วนที่ไม่เกี่ยวข้อง (เมนูนำทาง, footer, sidebar)
4. คลิก **Save** เพื่ออัปเดต

<Callout type="info">
  แก้ไขได้เฉพาะหน้าที่มีสถานะ "Pending" เท่านั้น เมื่อเริ่มประมวลผลแล้ว หน้าจะไม่สามารถเปลี่ยนแปลงได้
</Callout>

### เลือกและประมวลผลหน้า

1. ใช้ checkbox เพื่อเลือกหน้าที่ต้องการเก็บ
2. ใช้ **Select All** เพื่อเลือกหน้า pending ทั้งหมดพร้อมกัน
3. เลือกโฟลเดอร์ปลายทางหากต้องการ
4. คลิก **Process Selected**

หลังจากเริ่มประมวลผล คุณจะถูกสลับไปที่แท็บ **Documents** โดยอัตโนมัติ ซึ่งเอกสารใหม่จะปรากฏ

## สถานะ Crawl

| สถานะ | ความหมาย |
|-------|----------|
| Pending | Crawl อยู่ในคิวรอเริ่ม |
| In Progress | กำลังเยี่ยมชมหน้าเว็บ |
| Completed | Crawl หน้าที่เข้าถึงได้ทั้งหมดแล้ว |
| Partial Success | Crawl บางหน้าสำเร็จ บางหน้าล้มเหลว |
| Failed | Crawl ไม่สามารถทำให้เสร็จสิ้นได้ |
| Cancelled | หยุดโดยคุณ |

## การคงอยู่ของ Session

Session การ crawl จะคงอยู่แม้เปลี่ยนหน้าหรือ refresh:
- Crawl ที่กำลังทำงานจะกู้คืนโดยอัตโนมัติเมื่อกลับมาที่แท็บ Website
- Crawl ที่เสร็จแล้วจะพร้อมให้ตรวจสอบได้สูงสุด 1 ชั่วโมง

## เคล็ดลับ

- ตรวจสอบและแก้ไขเนื้อหาที่ crawl ก่อนประมวลผลเพื่อปรับปรุงคุณภาพ
- ใช้ "Single page only" สำหรับหน้าเดียวที่ต้องการเพิ่มอย่างรวดเร็ว
- เปิด "Respect robots.txt" ไว้เพื่อเคารพการตั้งค่าของเจ้าของเว็บไซต์
- เอกสารที่ crawl จะปรากฏในแท็บ Documents เป็นไฟล์ Markdown (.md)

## คำถามที่พบบ่อย

**ถาม: Crawl ได้กี่หน้า?**
ตอบ: จำนวนหน้าสูงสุดขึ้นอยู่กับ plan ของคุณ Crawler จะติดตาม link จาก URL เริ่มต้นของคุณจนถึงขีดจำกัดความลึกที่ตั้งค่าไว้

**ถาม: สามารถ crawl หน้าที่ต้อง login ได้หรือไม่?**
ตอบ: ไม่ได้ Crawler สามารถเข้าถึงเฉพาะหน้าสาธารณะเท่านั้น หน้าที่อยู่หลัง authentication จะถูกข้าม

**ถาม: หน้าที่ crawl เป็นรูปแบบอะไร?**
ตอบ: เนื้อหาจะถูกดึงเป็นเอกสาร Markdown (.md) และประมวลผลผ่าน pipeline มาตรฐาน (chunking, embedding และ search indexing)

**ถาม: ทำไมบางหน้าล้มเหลว?**
ตอบ: หน้าอาจล้มเหลวเนื่องจากการป้องกัน bot (firewall เช่น Cloudflare), server error หรือเนื้อหาว่าง Crawl จะแสดงสถานะ "Partial Success"

**ถาม: สามารถ crawl เว็บไซต์เดิมอีกครั้งได้หรือไม่?**
ตอบ: ได้ เริ่ม crawl ใหม่ด้วย URL เดิม หน้าที่ crawl ก่อนหน้าจะถูกแทนที่เมื่อเริ่ม crawl ใหม่

**ถาม: หน้าที่ประมวลผลแล้วปรากฏที่ไหน?**
ตอบ: ในแท็บ **Documents** ของหน้า Content จะปรากฏเป็นไฟล์ Markdown (.md)

## การแก้ไขปัญหา

### หน้าส่งคืน error 403 หรือ 503

เว็บไซต์อาจบล็อก crawler อัตโนมัติ ตัวเลือก:
- ขอให้เจ้าของเว็บไซต์ whitelist `CuneiformBot/1.0`
- ลอง crawl หน้าเฉพาะด้วย "Single page only"

### เนื้อหาว่างหรืออ่านไม่ออก

บางเว็บไซต์ใช้ JavaScript rendering จำนวนมาก Crawler รองรับ framework สมัยใหม่ส่วนใหญ่ แต่:
- Single-page app ที่ต้อง authentication จะไม่ทำงาน
- เนื้อหาที่โหลดผ่าน infinite scroll อาจถูกจับเพียงบางส่วน

### Crawl ช้า

- แต่ละหน้าใช้เวลาสักครู่ในการ crawl (รวม rendering และ rate limiting)
- เว็บไซต์ขนาดใหญ่ที่มีหลายหน้าจะใช้เวลาหลายนาที
- สามารถยกเลิกและลองใหม่ได้หาก crawl ดูเหมือนค้าง
