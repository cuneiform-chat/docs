# Order

**"আমার order কোথায়?" — একটি store যত প্রশ্ন পায় তার মধ্যে এটিই সবচেয়ে বেশি।** একটি store যুক্ত থাকলে আপনার agent সেটির উত্তর দেয় — আসল order থেকেই — কোনো মানুষের কাছে না পাঠিয়ে।

Order খোঁজা **Shopify** ও **WooCommerce**-এ একইভাবে কাজ করে। দুটি বিষয় আলাদা, আর দুটিই নিচে যেখানে প্রাসঙ্গিক সেখানেই বলা আছে: কোন platform কতটা shipping-এর বিবরণ দিতে পারে, আর — Shopify-এ — আপনার app গ্রাহকের কোন তথ্যগুলো পড়ার অনুমোদন পেয়েছে।

## Order খোঁজা (WISMO) [#order-lookup-wismo]

একজন ক্রেতা chat-এ তার order নিয়ে জিজ্ঞাসা করে। agent order নম্বর ও একটি যোগাযোগের তথ্য চায়, দুটিই আসল order-এর সাথে মিলিয়ে দেখে, এবং উত্তর দেয়।

### যাচাইকরণই পুরো নকশা [#verification-is-the-whole-design]

agent order-এর বিবরণ কেবল তখনই প্রকাশ করবে যখন ক্রেতা **দুটিই** দেয়:

1. **হুবহু order নম্বর**, এবং
2. **সেই order-এ থাকা ইমেইল বা ফোন নম্বরের সাথে মিলে যায় এমন একটি**

মেলানোটি লেখার ধরন নিয়ে উদার, পরিচয় নিয়ে নয়। ইমেইলে ছোট-বড় হাতের অক্ষরে কিছু যায় আসে না; ফোন নম্বর অঙ্ক ধরে ধরে মেলানো হয়, তাই `+1 (555) 010-9999` আর `15550109999` একই নম্বর।

### ক্রেতা যা ফেরত পায় [#what-the-shopper-gets-back]

একটি যাচাইকৃত খোঁজা order-এর অবস্থা ফেরত দেয়, store যতটুকু fulfillment-এর বিবরণ দিতে পারে ততটুকু, আর — যেখানে পাওয়া যায় — আপনার নিজের store-এ order-টির একটি লিঙ্ক।

কতটা shipping-এর বিবরণ ফেরত আসে তা platform-এর উপর নির্ভর করে। Shopify প্রতিটি fulfillment-এর জন্য courier, tracking ও ডেলিভারির তারিখ দেয়। WooCommerce-এ fulfillment-এর কোনো অন্তর্নির্মিত রেকর্ড নেই: courier ও tracking আসে একটি shipment-tracking plugin থেকে। সেটি না থাকলে একটি WooCommerce উত্তর order-এর অবস্থা বহন করে, কিন্তু কোনো courier বা tracking নম্বর নয়।

একজন ক্রেতা যিনি কথোপকথনে আগেই একটি order যাচাই করেছেন, তিনি প্রতিটি order আলাদাভাবে আবার যাচাই না করেই তার **সাম্প্রতিক order**-গুলোও চাইতে পারেন। **WhatsApp**-এ শর্টকাটটি সাথে সাথেই পাওয়া যায়, কারণ WhatsApp আগেই ক্রেতার ফোন নম্বর যাচাই করে রেখেছে এবং order সেই একই নম্বরের সাথেই মেলানো হয় — একজন ক্রেতা কেবল তার নিজের যাচাইকৃত নম্বরে দেওয়া order-ই দেখতে পান। অন্য প্রতিটি channel-এ এটি ততক্ষণ বন্ধ থাকে যতক্ষণ না তিনি সেই কথোপকথনে একটি order যাচাই করেন। যেভাবেই হোক, এটি কখনোই অন্য কারো order-এ ঢোকার পথ নয়।

### প্রয়োজনীয়তা [#requirements]

Order খোঁজার জন্য এমন একটি যুক্ত store লাগে যার order permission সুস্থ আছে। আপনার store-এর শংসাপত্র বাতিল হয়ে গেলে বা সংযোগ অসুস্থ হয়ে পড়লে agent একটি কথোপকথনের মাঝপথে ব্যর্থ হওয়ার বদলে order খোঁজার প্রস্তাব দেওয়াই বন্ধ করে দেয়। **Commerce → Shopify** বা **Commerce → WooCommerce**-এ সংযোগের অবস্থা দেখুন।

## Order-status আপডেট [#order-status-updates]

একজন ক্রেতা chat-এ একটি order যাচাই করার পর agent তাকে খবর দিতে থাকার প্রস্তাব দিতে পারে। তিনি রাজি হলে একই channel-এ, একই কথোপকথনের ভেতরে shipping আপডেট পান যেটি তিনি ইতিমধ্যেই ব্যবহার করছিলেন।

কেবল একটিই শর্ত খুলতে হয়, আর সেটি ক্রেতার হাতে: তাকে কথোপকথনে, তার order যাচাই করার পর, opt-in করতে হয়। আপনি কোনো ক্রেতার হয়ে তাকে subscribe করাতে পারেন না, আর কোনো ক্রেতা এমন order-এ subscribe করতে পারে না যেটি তার নিজের বলে সে প্রমাণ করেনি।

আপনার দিকে, একটি store যুক্ত হয়ে গেলে তিন ধরনের আপডেটই **ডিফল্টভাবে চালু** থাকে — আগে কিছু চালু করার নেই। **Commerce**-এ store-এর পাতায় আপনি সেগুলোর যেকোনোটি আলাদাভাবে বন্ধ করতে পারেন; একটি বন্ধ করলে সেই আপডেটটি প্রতিটি ক্রেতার জন্যই থেমে যায়, যারা আগেই opt-in করেছেন তাদের জন্যও।

### কী একটি আপডেট চালু করে [#what-triggers-an-update]

Order-এর অগ্রগতি থেকেই আপডেট ছোটে: যখন order-টি **পরিশোধিত বলে নিশ্চিত হয়**, যখন সেটি **পাঠানো হয়**, আর যখন **চালানের অবস্থা বদলায়**। এই channel দিয়ে বিপণনের মতো কিছুই কখনো পাঠানো হয় না; এটি আছে "আমার order কোথায়?"-এর উত্তর দিতে, ক্রেতাকে আবার জিজ্ঞাসা করতে হওয়ার আগেই।

WooCommerce ও Shopify-এর আপডেট একই ব্যবস্থার মধ্য দিয়ে পৌঁছায়, তাই order যে store থেকেই আসুক না কেন অভিজ্ঞতা একই।

## দুটি store যুক্ত থাকলে [#two-stores-one-experience]

প্রতিটি store-এর নিজের একটি store agent আছে, আর order খোঁজা সেই agent-এর নিজের store-এই চলে। আপনার Shopify store agent-কে একটি WooCommerce order নিয়ে জিজ্ঞাসা করলে সেটি খুঁজে পাওয়া যাবে না — দুটিতে একসাথে খোঁজা হয় না।

আপনি যদি দুটিতেই বিক্রি করেন, তাহলে ক্রেতারা যেখান থেকে কিনেছেন সেই store-এর agent-এর কাছে তাদের পাঠান, অথবা প্রতিটি store-কে নিজের আলাদা channel-এ রাখুন যাতে প্রশ্নটি শুরুতেই সঠিক জায়গায় পৌঁছায়।

## পর্দার আড়ালে: টুলের নাম [#behind-the-scenes-tool-names]

আপনি যদি একটি কথোপকথনের trace দেখেন, order টুলগুলোর নাম দেখবেন `shopify_order_status`, `shopify_list_orders` ও `subscribe_order_updates`।

<Callout type="info">
  **নামগুলো ঐতিহাসিক, আক্ষরিক নয়।** একই টুলগুলো WooCommerce store-কেও সেবা দেয়। কেবল WooCommerce ব্যবহার করা একজন বিক্রেতাও `shopify_order_status` নামের একটি টুলকে WooCommerce-এর খোঁজাটি করতে দেখবেন। কিছুই ভুল পথে যায় না — টুলগুলো আপনার আসলে যে store-গুলো যুক্ত আছে সেগুলোই খুঁজে নেয়।
</Callout>

## সমস্যা সমাধান [#troubleshooting]

### agent বলছে এমন একটি order খুঁজে পাচ্ছে না যেটি নিশ্চিতভাবেই আছে [#the-agent-says-it-cant-find-an-order-that-definitely-exists]

প্রায় সবসময়ই যোগাযোগের তথ্যটিই কারণ। ক্রেতা যে ইমেইল বা ফোন দিচ্ছেন সেটিকে **সেই order-এ থাকা**টির সাথে মিলতে হবে — তিনি সাধারণত যেটি ব্যবহার করেন সেটির সাথে নয়, আর তার অ্যাকাউন্টে থাকাটির সাথেও নয়। তাকে order নিশ্চিতকরণের ইমেইলটি দেখতে বলুন।

### agent order খোঁজার প্রস্তাবই দিচ্ছে না [#the-agent-wont-offer-order-lookup-at-all]

হয় কথোপকথনটি আপনার **store agent**-এর সাথে নয় (কেবল সেই agent-ই commerce টুল বহন করে), নয়তো store-এর সংযোগ অসুস্থ। **Commerce**-এর নিচে সংযোগের অবস্থা দেখুন।

### একজন ক্রেতা opt-in করেছে কিন্তু কোনো আপডেট পাচ্ছে না [#a-shopper-opted-in-but-gets-no-updates]

store সংযোগের নোটিফিকেশন toggle-গুলো দেখুন। সেগুলো ডিফল্টভাবে চালু থাকে, কিন্তু সংশ্লিষ্ট আপডেটের ধরনটি কোনো এক সময়ে বন্ধ করে দেওয়া হয়ে থাকলে কেবল ক্রেতার opt-in দিয়ে কোনো বার্তা তৈরি হবে না।

### অন্যথায় সঠিক একটি উত্তরে shipping-এর বিবরণ নেই [#shipping-details-are-missing-from-an-otherwise-correct-answer]

Order-টি পাওয়া ও যাচাই হয়েছে, কিন্তু fulfillment-এর কিছু অংশ পড়া যায়নি। agent পুরো খোঁজাটি ব্যর্থ করার বদলে তার কাছে যা আছে তা দিয়েই উত্তর দেয়। **WooCommerce**-এ এর মানে সাধারণত কোনো shipment-tracking plugin ইনস্টল করা নেই, তাই জানানোর মতো কোনো courier বা tracking নম্বরই নেই।

### Shopify-এ order পাওয়া যাচ্ছে কিন্তু ফোন যাচাই ব্যর্থ হচ্ছে বা order-এর লিঙ্ক নেই [#on-shopify-the-order-is-found-but-phone-verification-fails-or-the-order-link-is-missing]

গ্রাহকের কিছু তথ্য — order-এ থাকা ফোন নম্বর, আর order-এর status পাতার লিঙ্ক — Protected Customer Data, আর আপনার app সেগুলো পড়ার অনুমোদন না পাওয়া পর্যন্ত Shopify সেগুলো আটকে রাখে। agent খোঁজাটি ব্যর্থ করার বদলে সে যা পড়তে পারে তা দিয়েই উত্তর দেয়। কোনো তথ্য আটকে থাকা অবস্থায় ফোনভিত্তিক যাচাই মিলতে পারে না: ক্রেতাকে বরং order-এ থাকা ইমেইলটি ব্যবহার করতে বলুন।
