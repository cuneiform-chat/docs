# Shopify

**একবার আপনার Shopify store যুক্ত করুন, তারপর আপনার agent আপনার catalog, order আর inventory থেকেই উত্তর দেবে।** সেটআপে লাগে প্রায় পাঁচ মিনিট, পুরোটাই হয় Cuneiform Chat-এর ভেতরে — theme বদলানোর দরকার নেই, কোনো plugin-ও লাগে না।

</Callout>

## আপনি যা পান [#what-you-get]

store যুক্ত হয়ে গেলে আপনার store agent পারে:

- **catalog-এর প্রশ্নের উত্তর দিতে** — আপনার আসল product, variant, option আর দাম থেকে
- **সিঙ্ক হওয়া catalog থেকে stock আর দাম পড়তে**, যা webhook দিয়ে হালনাগাদ থাকে, তাই সদ্য ফুরিয়ে যাওয়া জিনিস সে আর কাউকে দেয় না
- **stock-এ আছে এমন product সুপারিশ করতে**, মুখস্থ কিছু নয়
- **order খুঁজে দিতে** — যে ক্রেতা প্রমাণ করতে পারেন order-টি তাঁরই
- **order-এর status আপডেট পাঠাতে** — যাঁরা চেয়েছেন তাঁদের, একই চ্যাটে
- **কিনতে প্রস্তুত ক্রেতাকে আপনার Shopify checkout-এ পৌঁছে দিতে**, পুরো cart অক্ষত রেখে

## পূর্বশর্ত [#prerequisites]

- একটি **Shopify store** যেটি আপনি চালান
- একটি Cuneiform Chat workspace, আর তাতে একটি **Owner বা Admin** অ্যাকাউন্ট — store যুক্ত করা admin-এর কাজ
- অন্তত একটি agent, বা plan-এ নতুন একটি বানানোর জায়গা (দেখুন [আপনার store agent](/commerce#your-store-agent))

<Callout type="warning">
  **collaborator অ্যাকাউন্ট দিয়ে সেটআপ শেষ করা যায় না।** এর একটি অংশ হয় আপনার Shopify admin-এর Dev Dashboard-এ, যেটি Shopify collaborator অ্যাকাউন্টকে দেয় না। কোনো এজেন্সি যদি আপনার store দেখে, তবে ওই অংশটি store-এর মালিক — বা app-এর অনুমতি আছে এমন কোনো staff অ্যাকাউন্ট — কে করতে হবে।
</Callout>

## যুক্ত হওয়া যেভাবে কাজ করে [#how-connecting-works]

আপনি নিজের Shopify admin-এর ভেতরেই ছোট একটি app বানান, সেটি নিজের store-এ install করেন, আর তার credential দুটি Cuneiform Chat-এ পেস্ট করেন। আপনার store-এর data অন্য কোনো পথে আপনার Shopify অ্যাকাউন্ট ছাড়ে না, আর app-টির মালিক আমরা নই — আপনি।

**ধাপে ধাপে নির্দেশনাটি প্রোডাক্টের ভেতরেই থাকে**, কারণ সেখানে আপনার store-এর জন্য ঠিক কোন মানগুলো বসাতে হবে তা দেখানো যায় — সেগুলো নির্ভর করে আপনার workspace আর আমরা এখন যে API version চালাচ্ছি তার উপর, তাই এখানে একটি কপি রাখলে সেটি নীরবেই পুরোনো হয়ে যেত।

শুরু করতে: Cuneiform Chat-এ **Commerce → Shopify** খুলুন আর connect স্ক্রিনের ধাপগুলো অনুসরণ করুন। সেটি আপনাকে app বানানো, নিচের permission গুলো চাওয়া, install করা আর credential পেস্ট করা — সবটাই দেখিয়ে দেয়।

<Callout type="info">
  **app install করাটা আলাদা একটি ধাপ।** Shopify-র Dev Dashboard-এ app-এর একটি version release করা আর সেটিকে store-এ install করা এক জিনিস নয়। release-এ থেমে গেলে credential পেস্ট করার সময় সেগুলো প্রত্যাখ্যাত হয় — আর তেমন হলে connect স্ক্রিন সেটি স্পষ্ট করেই বলে দেয়।
</Callout>

## আমরা যেসব permission চাই [#permissions-we-ask-for]

আপনার app **পাঁচটি read-only permission** চায়। এর মধ্যে লেখার (write) কোনো permission নেই — আপনার store-এর কিছুই সে বদলাতে পারে না।

| Permission | কেন দরকার |
|---|---|
| `read_products` | আপনার catalog পড়া: product, variant, option, দাম, ছবি |
| `read_inventory` | stock পড়া, যাতে agent শুধু যা আছে তা-ই সুপারিশ করে |
| `read_orders` | ক্রেতার order খুঁজে দেওয়া আর তাঁকে status আপডেট পাঠানো |
| `read_fulfillments` | ওই order গুলোর শিপিং অগ্রগতি জানানো |
| `read_customers` | ক্রেতার ফোন নম্বর যে order নিয়ে প্রশ্ন, তার সঙ্গে মিলিয়ে দেখা |

<Callout type="info">
  **read-only মানে সত্যিই শুধু পড়া।** app কোনো product বানাতে, বদলাতে বা মুছতে পারে না; stock বদলাতে পারে না; order বানাতে, বদলাতে বা বাতিল করতে পারে না; আর টাকা নিতেও পারে না। প্রতিটি কেনাকাটা শেষ হয় আপনার নিজের Shopify checkout-এ।
</Callout>

### কোনো permission না পাওয়া গেলে [#if-a-permission-isnt-granted]

Shopify তার সবচেয়ে সস্তা plan গুলোতে customer আর order-এর অ্যাক্সেস সীমিত রাখে, তাই Basic বা Starter-এ থাকা store হয়তো `read_orders` বা `read_customers` দিতেই পারবে না। তেমন হলেও সংযোগ হয়ে যায়, আর কোন permission গুলো নেই তা Cuneiform Chat আপনাকে জানায় — connect স্ক্রিনে, এবং ঘাটতিটি যতদিন সত্যি ততদিন **Commerce → Shopify → Connection**-এও।

অনুপস্থিত permission-এর উপর নির্ভরশীল সবকিছু নীরবে ব্যর্থ না হয়ে বন্ধ থাকে; সাধারণত এতে বাদ পড়ে order খোঁজা আর status আপডেট। আপনার store-এর plan সেগুলো কভার করা শুরু করলে store-টি disconnect করে আবার connect করুন, তাহলে নতুন permission গুলো ধরা পড়বে।

## Shopify admin-এর ভেতরেই Cuneiform Chat খোলা [#opening-inside-shopify-admin]

চাইলে আপনার app-কে **embedded** হিসেবে চিহ্নিত করতে পারেন, তাতে আপনার Cuneiform Chat dashboard `admin.shopify.com`-এর ভেতরেই খুলবে, store-এর বাকি administration-এর পাশে — setup, connection status, configuration আর একটি dashboard। Shopify যে দুটি মান চায়, connect স্ক্রিন সেগুলো দিয়ে দেয়। এটি বাদ দিলে integration-এর কাজে কিছুই বদলায় না; শুধু আপনি কোথা থেকে সেটি খুলবেন তা বদলায়।

## প্রতি workspace-এ একটি store [#one-store-per-workspace]

একটি workspace **একটি Shopify store** যুক্ত করে। একই সঙ্গে একটি WooCommerce store-ও যুক্ত থাকতে পারে — দেখুন [Commerce](/commerce#you-can-connect-both-at-once)।

অন্য কোনো workspace-এ ইতিমধ্যে যুক্ত আছে এমন store যুক্ত করতে গেলে চেষ্টাটি নীরবে দখল না করে বরং ফিরিয়ে দেওয়া হয়।

## পরে permission বা credential বদলানো [#changing-permissions-or-credentials-later]

আলাদা কোনো "Reconnect" বোতাম নেই। আপনার app-এর permission আর credential যুক্ত হওয়ার সময়ই লিপিবদ্ধ হয় এবং পরে আর নতুন করে লেখা হয় না — তাই Shopify-তে করা যেকোনো বদল (নতুন scope যোগ করা, client secret বদলানো) Cuneiform Chat-এ পৌঁছায় **store-টি disconnect করে আবার connect করলে**।

<Callout type="warning">
  আবার connect করলে [Disconnect করা](#disconnecting)-য় বর্ণিত পুরো teardown আবার চলে, তাই store-এর সঙ্গে যুক্ত Storefront থাকলে আগে ওই অংশটি পড়ে নিন।
</Callout>

## যুক্ত হওয়ার পরে [#after-you-connect]

- **আপনার catalog সঙ্গে সঙ্গেই sync হতে শুরু করে।** sync কী কী ধরে আর কীভাবে হালনাগাদ থাকে, দেখুন [Catalog ও Knowledge](/commerce/catalog-and-knowledge)।
- **একটি agent হয়ে যায় আপনার store agent**, যুক্ত হওয়ার সময়ই আপনার হয়ে বেছে নেওয়া। দেখুন [আপনার store agent](/commerce#your-store-agent)।
- **order status আপডেট ডিফল্টে চালু থাকে**, আর একমাত্র শর্তটি ক্রেতার নিজের: order যাচাই করার পর তিনি সেটি চেয়ে নেন। দেখুন [Order](/commerce/orders#order-status-updates)।

## সমস্যা সমাধান [#troubleshooting]

### credential প্রত্যাখ্যাত হলো [#the-credentials-were-rejected]

দশবারের নয়বারই কারণ হলো app **release** হয়েছে কিন্তু store-এ কখনো **install** হয়নি — Shopify-র Dev Dashboard-এ এ দুটি আলাদা কাজ। connect স্ক্রিন এই ক্ষেত্রটিকে সত্যিকারের credential ভুলের থেকে আলাদা করে দেখায়, তাই Client ID আর Secret ভুল ধরে নেওয়ার আগে সেখানকার বার্তাটি পড়ুন।

### order খোঁজা আর শিপিং আপডেট পাওয়া যাচ্ছে না [#order-lookup-unavailable]

**Commerce → Shopify → Connection**-এ permission-ঘাটতির নোটিশ আছে কি না দেখুন। Shopify-র সবচেয়ে সস্তা plan গুলোতে `read_orders` আর `read_customers` আদৌ দেওয়া না-ও যেতে পারে — দেখুন [কোনো permission না পাওয়া গেলে](#if-a-permission-isnt-granted)।

### যুক্ত হওয়ার ঠিক পরেই catalog খালি [#the-catalog-is-empty-right-after-connecting]

প্রথম import পুরো catalog নিয়ে আসে, আর বড় store-এ তাতে কয়েক মিনিট লাগে। তারপরও খালি দেখালে **Commerce → Shopify → Catalog & Data** থেকে **Re-sync now** চালান। catalog যতক্ষণ খালি, Overview ট্যাবের checklist-এও এক ক্লিকের **Sync now** থাকে।

### agent product-এর প্রশ্নের উত্তর দিচ্ছে না [#the-agent-isnt-answering-product-questions]

দেখুন আপনি **store agent**-এর সঙ্গেই কথা বলছেন কি না — যুক্ত হওয়ার সময় store-এর সঙ্গে যেটি বাঁধা হয়েছিল। তার agent পাতায় একটি read-only প্যানেল থাকে, যাতে লেখা থাকে এটি আপনার store দিয়ে পরিচালিত। বাকি agent গুলো commerce-এর টুল বহন করে না।

### একজন Member store যুক্ত করতে পারছে না [#a-member-cant-connect-the-store]

store যুক্ত করতে **Integration connect** permission লাগে, যা Owner আর Admin-দের আছে, Member-দের নেই।

## Disconnect করা [#disconnecting]

**Commerce → Shopify → Disconnect** থেকে disconnect করুন। disconnect করলে:

- সংরক্ষিত সংযোগ আর sync হওয়া catalog মুছে যায়
- ওই catalog থেকে বানানো product knowledge মুছে যায়, তাই agent আর সেখান থেকে উত্তর দেয় না
- store agent-এর commerce অনুমোদন রিসেট হয়, আপনি কখনো সম্পাদনা না করে থাকলে তার commerce persona আগের অবস্থায় ফেরে, আর **agent-টি নিজেই archive হয়ে যায়** — একই store আবার যুক্ত করলে তার টিউনিং আর version ইতিহাস অক্ষত রেখেই সেটি ফিরে পাওয়া যায়
- **ওই store-এর সঙ্গে যুক্ত যেকোনো Storefront স্থায়ীভাবে মুছে যায়**, সঙ্গে তার analytics ইতিহাসও। হাতে বানানো Storefront-এ হাত পড়ে না
- store-এর সঙ্গে আসা commerce Agent Form গুলো archive হয়
- AI-এর বানানো quiz সাজেশন একেবারেই মুছে যায়, যাতে ভবিষ্যতে আবার যুক্ত করলে শুরুটা পরিষ্কার হয়

<Callout type="warning">
  আপনার যদি এখনো একটি **WooCommerce** store যুক্ত থাকে, তবে কেবল পুরো workspace জুড়ে প্রযোজ্য ধাপ দুটি বাদ যায় — commerce Agent Form archive করা আর quiz সাজেশন মোছা। Shopify store-এর নিজস্ব catalog, product knowledge, Storefront, analytics আর store agent সবসময়ই সরিয়ে ফেলা হয়।
</Callout>

**আপনার app আপনার Shopify admin-এ install হয়েই থাকে।** এখানে disconnect করলে সম্পর্কের আমাদের দিকটি সরে যায়, আপনার বানানো app নয় — সেটি আপনার store-এর। একেবারে সরাতে চাইলে Shopify admin থেকে সেটি মুছে দিন।
