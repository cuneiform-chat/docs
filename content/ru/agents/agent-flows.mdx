# Agent Flows

Многоэкранные формы, которые ИИ-agent может предложить клиенту прямо посреди разговора. Agent сам решает, когда запросить структурированные данные — имя, даты, фото документа, многошаговую анкету — и клиент заполняет их в нативной форме, а не в долгой переписке.

## Поддерживаемые каналы

Flow не зависит от канала: вы создаёте его один раз, и он отображается нативно везде, где работает agent.

| Канал | Как открывается форма | Примечания |
|-------|-----------------------|------------|
| **WhatsApp** | Agent отправляет нативную кнопку WhatsApp Flow; форма открывается внутри WhatsApp | Публикуется по языкам в Meta; единственный канал с ограничениями форматированного текста со стороны WhatsApp |
| **Telegram** | Agent отправляет inline-кнопку, открывающую форму как Telegram Mini App | Полное форматирование (жирный, заголовки, списки, таблицы) |
| **Messenger** | Agent отправляет кнопку, открывающую форму в Messenger Webview | Полное форматирование |
| **Чат-виджет на сайте** | Форма открывается прямо во встроенном чат-виджете на вашем сайте | Лёгкий рендерер; форматирование ограничено жирным, курсивом, ссылками и списками |

Одни и те же компоненты, экраны, логика и переводы работают на всех каналах — поддерживать что-то отдельно для каждого канала не нужно. Условная логика (**If** / **Switch**) и переходы между экранами вычисляются одинаково в каждом рендерере, поэтому flow ведёт себя идентично, где бы клиент его ни заполнял.

**Публикуйте один flow сразу в нескольких каналах.** На вкладке **Распространение** у каждого канала своя карточка публикации. Опубликуйте на номере WhatsApp, затем опубликуйте *тот же* flow в Telegram-боте и на странице Messenger: каждая карточка остаётся опубликованной независимо, и добавление одного канала никогда не снимает с публикации другой. Снимите с публикации отдельный канал из его карточки, не трогая остальные. Аналитика по умолчанию объединяется по всем каналам, где flow активен; когда flow активен в двух и более каналах, в разделах «Отправки», «Тепловая карта» и «Диагностика» появляется **фильтр по каналу**, чтобы анализировать по одному каналу за раз.

## Когда использовать Agent Flows

Выбирайте flow, когда обычный чат — неподходящая форма для вопроса:

- **Сбор лидов** — имя + e-mail + размер компании + предпочтительное время встречи, всё на одном экране, который клиент заполняет за один раз
- **Запись на приём** — выбрать дату, выбрать время, подтвердить
- **Загрузка документов или фото** — собрать удостоверение, чек, фото повреждённого товара
- **Многошаговый приём заявок** — чек-листы симптомов, анкеты, опросы
- **Условные вопросы** — спрашивать «какое у вас домашнее животное?» только если на «есть ли у вас домашнее животное?» ответили «да»

Agent рекомендует flow, когда его системный prompt + контекст разговора совпадают. Вы настраиваете flow один раз в панели администратора; agent переиспользует его в каждом разговоре.

## Создание flow

Flows находятся в разделе **Agent Flows** в панели администратора клиента. У каждого flow есть:

- **Имя и описание**, которые agent читает, чтобы решить, когда его использовать
- Один или несколько **экранов**, каждый из которых содержит **компоненты** (поля)
- Необязательная **логика экранов** (переход на разные экраны в зависимости от выбора клиента)
- Необязательные **A/B-варианты** — разделение трафика между двумя версиями одного flow
- **Публикации** по языкам в WhatsApp (переведите один раз, публикуйте по языкам)

## Начать с шаблона

Необязательно начинать с пустого редактора. Откройте вкладку **Шаблоны** в списке Agent Flows, чтобы просмотреть подобранную библиотеку готовых flows — захват лидов, запись на демо, приём обращений в поддержку, отзывы о продукте и другое. Нажмите **Использовать этот шаблон**, и в вашем рабочем пространстве создаётся редактируемый черновик: экраны, поля, логика и переводы уже заполнены. Привяжите черновик к номеру WhatsApp, измените всё, что нужно, и опубликуйте.

Шаблон — это лишь отправная точка: после создания копии это обычный flow, который полностью принадлежит вам и который можно свободно редактировать. Библиотека шаблонов доступна на всех тарифах, где есть Agent Flows.

## Библиотека компонентов — 23 варианта

Меню **Add field** в редакторе группирует все 23 компонента по семи категориям. Выберите форму, подходящую для нужных вам данных.

### Display (отображение, без ввода)

Эти компоненты показывают текст или изображения на экране, ничего не запрашивая у клиента.

| Компонент | Для чего |
|-----------|-----------|
| **Text Heading** | Крупный заголовок в верхней части экрана (≤ 80 символов) |
| **Text Subheading** | Вторичный заголовок под основным (≤ 80 символов) |
| **Text Body** | Абзац поясняющего текста. Поддерживает **полужирный** и ~~зачёркнутый~~ (≤ 4096 символов) |
| **Text Caption** | Короткий вспомогательный текст; разрешён markdown (≤ 4096 символов) |
| **Rich Text** | Блок markdown — удобно для условий, оговорок, форматированных инструкций |
| **Image** | Одно изображение (≤ 100 КБ) |
| **Image Carousel** | До 10 пролистываемых изображений с подписями — галереи товаров, «до/после», инструкции |

### Inputs (однострочный и многострочный текст)

| Компонент | Для чего |
|-----------|-----------|
| **Text Input** | Однострочное текстовое поле — имя, e-mail, короткие ответы |
| **Text Area** | Многострочное текстовое поле — комментарии, описания, более длинные ответы (≤ 600 символов) |
| **Embedded Link** | Встроенная ссылка, открываемая по нажатию, с произвольным текстом (≤ 25 символов) |

### Choices (выбор из набора)

| Компонент | Для чего |
|-----------|-----------|
| **Dropdown** | Выбрать один пункт из длинного списка (10+ вариантов) |
| **Radio Buttons** | Выбрать один пункт из короткого списка (≤ 5 вариантов), все видны сразу |
| **Checkboxes** | Выбрать любое число пунктов из списка, с необязательными минимумом и максимумом |
| **Chips Selector** | Выбор из не более чем 20 чипов-меток — интересы, категории, множественный выбор при компактном виде |

### Дата и время

| Компонент | Для чего |
|-----------|-----------|
| **Date Picker** | Одна дата — дата брони, дата рождения |
| **Calendar Picker** | Календарь с необязательным диапазоном дат, границами min/max и затемнёнными недоступными датами — запись на приём, проживание в отеле |

<Callout type="info">
  `Date Picker` и `Calendar Picker` оставлены как отдельные компоненты. Используйте **Date Picker** для быстрого выбора одной даты; используйте **Calendar Picker**, когда нужна видимая сетка месяца, диапазон или затемнение конкретных дат.
</Callout>

### Загрузка файлов

| Компонент | Для чего |
|-----------|-----------|
| **Photo Picker** | Клиент загружает фото с камеры или из галереи (до 30 за отправку) |
| **Document Picker** | Клиент загружает документы — PDF, DOC и т. д. (до 10 за отправку) |

<Callout type="warning">
  **Взаимное исключение:** На одном экране может быть либо Photo Picker, **либо** Document Picker, но не оба сразу. Разместите их на разных экранах, если вашему flow нужны оба типа загрузки.
</Callout>

### Layout

| Компонент | Для чего |
|-----------|-----------|
| **Navigation List** | До 20 нажимаемых строк со стрелками — выбрать категорию, выбрать товар, выбрать экран назначения |
| **Opt-In** | Флажок согласия — условия обслуживания, согласие на маркетинг, согласие по GDPR |
| **Footer** | Элемент отправки на последнем экране flow |

### Logic (условный рендеринг)

| Компонент | Для чего |
|-----------|-----------|
| **If** | Показывать некоторые компоненты, только когда условие истинно (`then`) — при необходимости с альтернативой (`else`) |
| **Switch** | Показывать разные компоненты в зависимости от значения, выбранного клиентом ранее (несколько `cases` + необязательный `default`) |

<Callout type="info">
  **If** и **Switch** поддерживают до **3 уровней вложенности**. Если вложенность получается глубже, лучше разнесите логику по нескольким экранам с маршрутизацией на уровне экранов.
</Callout>

## Многоэкранные flows и маршрутизация

Flow может содержать до **10 экранов**. Каждый экран завершается **Footer**, который отправляет flow или переходит к следующему экрану. Используйте редактор **логики экранов**, чтобы направлять клиента на разные следующие экраны в зависимости от его выбора — например, клиенты, выбравшие «Возврат», попадают на отдельный второй экран по возвратам; все остальные — на общий экран дальнейших действий.

Для условного рендеринга на уровне компонентов внутри одного экрана используйте **If** / **Switch**.

## Локализация

Flows публикуются по языкам. Переведите flow один раз, а затем выберите языки публикации из **полного списка языков, поддерживаемых WhatsApp** — всех языков, на которых Meta разрешает публиковать WhatsApp Flow. Там, где это важно, в списке показаны варианты с разбивкой по регионам: вы можете опубликовать **Português (Brasil)** отдельно от **Português (Portugal)** или **中文 (简体)** отдельно от **中文 (繁體)**. Каждый клиент видит версию, соответствующую языку его WhatsApp; если язык клиента не опубликован, в качестве резервного используется язык интеграции по умолчанию. (Если клиент пишет на базовом языке, например на португальском, а вы опубликовали только региональный вариант, такой как бразильский португальский, он всё равно получит локализованную форму.)

## A/B-тестирование

Если вы хотите сравнить две версии flow, настройте их как **варианты** на вкладке Variants. Клиенты разделяются детерминированно (один и тот же клиент всегда видит один и тот же вариант); представление **Submissions** показывает, из какого варианта пришла каждая отправка, а **Field Heatmap** позволяет сравнивать показатели отказов и завершений бок о бок.

## Генерация с помощью ИИ

Если у вас тариф более высокого уровня, редактор предлагает **генерацию форм с помощью ИИ**: напишите однострочный prompt («форма бронирования отеля с диапазоном дат и загрузкой фото») или загрузите PDF / изображение существующей формы, и ассистент составит flow за вас. Черновик полностью редактируем — каждое поле обратимо в редакторе (без непрозрачных снимков ИИ).

## Отправки и аналитика

После публикации flow каждая отправка попадает в представление **Submissions** этого flow. В каждой строке показано:

- Кто отправил, когда и через какого agent
- Полные значения полей формы
- **Оценка ИИ** (0–100), которую ассистент присвоил отправке — самые ценные лиды поднимаются наверх
- Реплики разговора **непосредственно перед** открытием формы (соединение с контекстом разговора — чтобы понять, почему agent решил запросить эту отправку)

Сводная аналитика включает **полосу KPI** (начато / завершено / доля отказов), **Field-Level Heatmap**, показывающую, где клиенты бросают форму, и **Narrative Diagnostic** — ИИ-аналитика, которому можно задать вопрос «почему люди уходят на экране 2?», и он проследит ответ по тепловой карте, отправкам и контексту разговора.

## Уведомления и воронка лидов

Отправка ценна, только если кто-то отреагирует быстро. На вкладке **Распространение** каждого потока есть блок уведомлений, чтобы нужные люди узнавали о лиде в момент его поступления:

- **Уведомления об отправке** — когда форма отправлена, в приложении появляется уведомление со ссылкой прямо на эту отправку. Включается по каждому потоку отдельно.
- **Уведомления об ответе после перехвата** — когда кто-то из вашей команды отвечает лиду в WhatsApp, а клиент пишет снова, вы получаете второе уведомление — второй такт цикла скорости отклика.
- **Получатели email** — добавьте до десяти адресов, и каждая отправка также шлёт отложенное письмо со ссылкой на отправку, чтобы офлайн-сотрудники не упустили лид.

Болтливый клиент вас не завалит: всплеск сообщений сразу после отправки сворачивается в **одно** уведомление, а новое срабатывает только после того, как человек действительно ответил и клиент вернулся.

У каждого потока также есть **полоса воронки** на странице отправок — представление только для чтения, чтобы с одного взгляда видеть, на каком этапе находятся лиды:

| Этап | Значение |
|------|----------|
| **Отправлено** | все отправки потока |
| **Обработано ИИ** | агент продолжил разговор после формы |
| **Ответил человек** | кто-то из команды ответил вручную |
| **Решено** | разговор был архивирован |
| **Ожидает ответа человека** | уведомлено, но человек ещё не ответил — лиды в зоне риска |

Воронка — это **эвристическое представление** для управления пайплайном с одного взгляда, а не модель атрибуции выручки.

## Контекстные подтверждения

Когда клиент завершает форму, он видит мгновенное сообщение-подтверждение, которое вы задали в ней (в WhatsApp это нативный экран завершения). Вскоре агент отправляет ещё и **отдельное сообщение, ссылающееся на то, что клиент действительно заполнил** —«Готово, записал вас на вторник на 14:00. Что-нибудь ещё?»— чтобы разговор продолжился естественно, а не оставил клиента наедине со статичным «спасибо». Агент уже знает отправленные значения, поэтому подтверждение конкретное, а не шаблонное. Это сообщение-продолжение отправляется в WhatsApp, Telegram и Messenger.

Эта функция **включена по умолчанию** для каждой формы. Если вы предпочитаете, чтобы агент молчал после отправки, отключите **Подтверждать отправки** на вкладке **Распространение** формы. Подтверждение также автоматически отключается, когда кто-то из вашей команды перехватил разговор: вы не получите сообщение от ИИ поверх ответа человека.

## Поделиться формой как ссылкой для кампании

Опубликованные формы живут не только внутри разговоров, которые начинает агент. Откройте карточку **Ресурс кампании** на вкладке **Распространение** формы и создайте **ссылку для рассылки** — стандартную ссылку прямого чата WhatsApp (плюс скачиваемый **QR-код**), которую можно вставить в письмо, в описание профиля Instagram, в кнопку «Записаться на демо» или напечатать на листовке.

Когда человек нажимает ссылку, WhatsApp открывает чат с вашим номером и заранее подготовленным сообщением; пользователь нажимает «Отправить», и **нужная форма открывается первым же ответом** — без догадок и без приветствия ИИ между ними. Тот, кто нажал «Записаться на демо», сразу получает форму записи. Дальше агент ведёт остальной разговор как обычно.

У каждой ссылки есть **счётчик открытий**, чтобы видеть, сколько человек запустили форму через неё, и вы можете **отозвать** ссылку в любой момент. Если текст ссылки отредактировали или удалили перед отправкой либо ссылку отозвали, сообщение просто переходит в обычный разговор с ИИ — ничего не ломается.
