# Commerce

**اربط متجرك فيتوقّف الـ agents لديك عن التخمين.** فبدلًا من الإجابة من مستند تذكّر أحدهم تحديثه في الربع الماضي، يقرؤون كتالوجك الحقيقي، ومستويات مخزونك الحقيقية، وطلباتك الحقيقية — في اللحظة التي يسأل فيها المتسوّق.

يرتبط Cuneiform Chat بمنصّتَي تجارة، ويعاملهما كنِدَّين:

- **[Shopify](/commerce/shopify)** — يُثبَّت من Shopify App Store ويعمل كتطبيق مدمج داخل لوحة إدارة Shopify لديك.
- **[WooCommerce](/commerce/woocommerce)** — يرتبط بمتجرك المستضاف ذاتيًا عبر WooCommerce REST API.

## ماذا يمنحك ربط متجر [#what-connecting-a-store-gives-you]

| القدرة | ما يعيشه المتسوّق لديك | اقرأ المزيد |
|---|---|---|
| **أسئلة الكتالوج** | "هل يتوفّر القميص الكتّاني باللون الكحلي؟" — إجابة من منتجاتك ومتغايراتك وأسعارك الفعلية | [الكتالوج والمعرفة](/commerce/catalog-and-knowledge) |
| **المخزون الحالي** | يأتي المخزون والسعر من كتالوجك المتزامن، وتُبقيهما الـ webhooks حديثَين، فلا يَعِد الـ agent بشيء نفد لديك للتوّ | [الكتالوج والمعرفة](/commerce/catalog-and-knowledge) |
| **التوصيات** | "ما الذي يناسب هذا؟" — اقتراحات مقصورة على ما هو متوفّر فعلًا | [الكتالوج والمعرفة](/commerce/catalog-and-knowledge) |
| **البحث عن الطلب (WISMO)** | "أين طلبي؟" — إجابة بعد أن يُثبت المتسوّق أن الطلب طلبه | [الطلبات](/commerce/orders) |
| **تحديثات حالة الطلب** | المتسوّقون الذين يشتركون يتلقّون تحديثات الشحن في المحادثة نفسها | [الطلبات](/commerce/orders) |
| **التحويل إلى الدفع** | يُحوَّل المتسوّق الجاهز للشراء إلى صفحة الدفع الخاصة بك وسلّته كما هي | [Checkout](/commerce/checkout) |
| **الدردشة الشرائية** | بطاقات منتجات وسلّة ودفع داخل المحادثة نفسها | [الدردشة الشرائية](/commerce/shoppable-chat) |
| **Product Library وProduct Finder** | واجهة منتجات منسّقة، إضافة إلى استبيان موجَّه يوصي بمنتجات في نهايته | [أدوات المنتجات](/commerce/product-tools) |
| **Commerce Analytics** | ما طلبه المتسوّقون، وما عُرِض عليهم، وأين توقّفوا | [التحليلات](/commerce/analytics) |

## منصّتان، مجموعة ميزات واحدة [#two-platforms-one-set-of-features]

Shopify وWooCommerce نِدَّان هنا — لا منصّة أساسية وأخرى احتياطية. كل قدرة في الجدول أعلاه تعمل على المنصّتين. وحيث يختلف السلوك فعلًا، فذلك لأن المنصّة نفسها تختلف، وكل فرق مذكور في الصفحة التي تغطّيه:

| الفرق | Shopify | WooCommerce |
|---|---|---|
| **كيف تربط** | ثبّت من Shopify App Store، ثم اربط مساحة عملك من داخل التطبيق المدمج | أدخل رابط متجرك ووافق على تفويض لمرة واحدة، أو الصق مفاتيح API يدويًا |
| **إعادة التفويض لاحقًا** | لا خطوة إعادة ربط — تغييرات الصلاحيات تأتي مع التطبيق نفسه | **Reconnect** يعيد تشغيل الموافقة على متجرك |
| **المزامنة الأولى للكتالوج** | تبدأ تلقائيًا عند الربط | تبدأ تلقائيًا في المسار الموجَّه؛ أما مسار المفاتيح اليدوي فيحتاج إلى **Re-sync now** — راجع [WooCommerce](/commerce/woocommerce#after-a-manual-connect) |
| **حداثة المخزون** | تحديثات مخزون مخصّصة، فيصل التغيير الذي يمسّ المخزون وحده بنفسه خلال ثوانٍ | تصل تغييرات المخزون مع تحديثات المنتج، فينتظر التغيير الذي يمسّ المخزون وحده تعديلَ المنتج التالي أو التوفيق التالي |
| **التحويل إلى الدفع** | رابط سلّة واحد يغطّي كل البنود | يعتمد على الصلاحية التي تحملها مفاتيحك — راجع [Checkout](/commerce/checkout) |

## يمكنك ربط الاثنين معًا [#you-can-connect-both-at-once]

متجر واحد لكل منصّة ولكل مساحة عمل — و**يمكن أن يكون متجر Shopify ومتجر WooCommerce مربوطَين في الوقت نفسه**. هذه هي إعدادات تعدّد المتاجر التي يراها التاجر فعلًا: ليست خمسة متاجر Shopify، بل متجر Shopify ومتجر Woo جنبًا إلى جنب.

وعندما يكون الاثنان مربوطَين، تستعلم أدوات التجارة من **كل** متجر مربوط وتدمج الإجابات: يجمع بحث الكتالوج النتائج معًا، وتُجمَع أعداد المنتجات، ويُحلّ البحث عن منتج في المتجر الذي يملكه. أما التحليلات فتُبقيهما منفصلين، مع مُبدّل منصّة للتنقّل بينهما.

<Callout type="warning">
  لا يمكن ربط المتجر إلا بمساحة عمل واحدة في الوقت نفسه. وإذا كان أحدهم قد ربط المتجر نفسه في مكان آخر، تُرفَض محاولة الربط برسالة تطلب منك فصله هناك أولًا.
</Callout>

## أين يقع Commerce في لوحة الإدارة [#where-commerce-lives-in-the-admin-panel]

كل ما يخصّ التجارة يقع تحت **Commerce** في شريط التنقّل الجانبي:

| الصفحة | ما فيها |
|---|---|
| **Commerce** | الصفحة الرئيسية: اربط متجرًا، وشاهد حالة الربط، وتابع من حيث توقّفت |
| **Shopify** | ربط Shopify لديك — الحالة، ومزامنة الكتالوج، ومعرفة المنتجات، والإشعارات |
| **WooCommerce** | الشيء نفسه، لمتجر WooCommerce لديك |
| **Products** | [Product Library](/commerce/product-tools) الخاصة بك |
| **Storefront** | [Storefront](/integrations/telegram-mini-app) داخل الروبوت، بما في ذلك المتاجر المرتبطة بالكتالوج |
| **Product Finder** | [استبيان المنتجات](/commerce/product-tools#product-finder) وإرسالاته وخريطته الحرارية وتشخيصاته |
| **Commerce Analytics** | [Commerce Analytics](/commerce/analytics) وCommerce Analyst |

## agent المتجر لديك [#your-store-agent]

لا يُفعَّل Commerce لكل الـ agents دفعةً واحدة. فعند ربط متجر، **يصبح agent واحد هو agent المتجر لديك** — وهو الـ agent الذي يحمل أدوات التجارة ويقرأ كتالوجك.

ويُختار ذلك الـ agent لك، لا بواسطتك. فإذا سبق أن ربطت هذا المتجر نفسه، استُعيد agent المتجر السابق له، بضبطه وسجلّ إصداراته كما هما؛ وإلا أُنشئ agent جديد. ولا تدير هذا عبر مفتاح لكل agent: إذ يظهر agent المتجر في صفحة الـ agent نفسها كلوحة للقراءة فقط تقول "مُدار بواسطة متجرك"، فيبقى واضحًا دائمًا أيّ agent مرتبط بأيّ متجر.

<Callout type="info">
  إذا كانت مساحة عملك قد استنفدت حصّتها من الـ agents، فلا مجال لإنشاء agent متجر. وسيخبرك مسار الربط بذلك ويطلب منك أن **ترقّي خطتك، أو تؤرشف agent غير مستخدَم ثم تعيد ربط متجرك** لإتمام الإعداد. هذه هي النقطة الوحيدة التي تلامس فيها حدودك التجارةَ، وهي تتعلّق بعدد الـ agents لا بالتجارة نفسها.
</Callout>

## البدء [#getting-started]

1. **اختر منصّتك.** اتبع [Shopify](/commerce/shopify) أو [WooCommerce](/commerce/woocommerce) — مسارا الربط مختلفان تمامًا، والنتيجة واحدة.
2. **دع الكتالوج يتزامن.** يسحب الاستيراد الأول منتجاتك ومتغايراتك وأسعارك وصورك ومخزونك. راجع [الكتالوج والمعرفة](/commerce/catalog-and-knowledge).
3. **اسأل agent المتجر سؤالًا عن الكتالوج.** "ما المقاسات المتاحة للقميص الكتّاني؟" هو أسرع دليل على نجاح الأمر.
4. **فعّل ما تريده.** [تحديثات حالة الطلب](/commerce/orders#order-status-updates)، و[الدردشة الشرائية](/commerce/shoppable-chat)، و[استبيان Product Finder](/commerce/product-tools#product-finder) — كل منها مستقلّ عن الآخر.
