# Options de configuration

import { Callout } from 'nextra/components'

Guide détaillé de toutes les options de configuration de l'agent.

## Structure de la Page

La page d'édition de l'agent comporte trois onglets :

| Onglet | Objectif |
|-----|---------|
| **Configuration** | Paramètres principaux (statut, nom, persona, LLM, messages) |
| **Knowledge Access** | Contrôle des documents que l'agent peut utiliser |
| **Integrations** | Connexion à des canaux externes (Telegram, Discord, etc.) |

## Onglet Configuration

### Statut

Contrôlez la disponibilité de votre agent :

| Statut | Playground | Intégrations | Notes |
|--------|------------|--------------|-------|
| **Testing** | ✅ Activé | ❌ Désactivé | Par défaut pour les nouveaux agents. Testez avant la mise en production. |
| **Active** | ✅ Activé | ✅ Activé | Prêt pour une utilisation en production. |
| **Inactive** | ❌ Désactivé | ❌ Désactivé | Désactivé temporairement. |
| **Archived** | ❌ Désactivé | ❌ Désactivé | Masqué de la liste principale. |

<Callout type="warning">
  Si votre agent a des intégrations connectées et que vous passez d'Active à un autre statut, une boîte de dialogue de confirmation vous avertira que l'agent cessera de répondre sur les canaux connectés.
</Callout>

### Paramètres de Base

- **Name** — Identifie l'agent dans votre dashboard
- **Description** — Notes internes sur l'objectif de l'agent

### Configuration du LLM

Contrôlez le modèle AI qui anime votre agent.

**Mode par défaut (toggle Advanced désactivé) :**
- Utilise les valeurs par défaut du tier de votre organisation
- Affiche un encadré expliquant que les valeurs par défaut du tier sont en cours d'utilisation
- Recommandé pour la plupart des cas d'usage

**Mode Avancé (toggle Advanced activé) :**

| Paramètre | Description |
|---------|-------------|
| **Model** | Sélectionnez parmi les modèles AI disponibles selon votre plan |
| **Temperature** | Contrôle la créativité des réponses (0.0-2.0) |

#### Guide de Temperature

| Valeur | Comportement |
|-------|----------|
| 0.0 - 0.3 | Réponses ciblées et déterministes |
| 0.4 - 0.7 | Équilibre entre créativité et cohérence |
| 0.8 - 2.0 | Réponses plus créatives et variées |

**Recommandation :** Commencez à 0.3-0.5 pour du Q&A factuel basé sur des documents.

#### Show Document References

Ce toggle (toujours visible, indépendamment du mode Advanced) contrôle si l'agent inclut des citations de sources dans ses réponses :

- **Off** (par défaut) — Les réponses ne mentionnent pas les documents sources
- **On** — Les réponses incluent des références aux documents sources

<Callout type="important">
  Activez les références aux documents pour les cas d'usage exigeant de la transparence, comme les contenus juridiques, de conformité ou internes où les utilisateurs doivent vérifier les sources.
</Callout>

### Prise en Charge des Langues

Votre agent détecte automatiquement la langue de chaque message utilisateur et répond en conséquence — aucune configuration manuelle nécessaire. 176 langues sont prises en charge nativement, dont l'arabe, le français, l'allemand, l'espagnol, le turc, le chinois, le japonais et bien d'autres.

### Agent Persona

Les instructions qui contrôlent le comportement de l'agent. Voir [Agent Personas](/agents/agent-personas) pour les bonnes pratiques.

**Actions disponibles :**
- **Generate** — Ouvre l'[Agent Persona Builder](/agents/persona-builder)
- **Edit** — Ouvre un panneau coulissant pour rédiger ou modifier la persona directement

Cliquez sur la zone de texte de la persona pour ouvrir le panneau d'édition.

**Encadré Platform Rules :**
Cliquez pour voir les règles de fiabilité de la plateforme appliquées automatiquement à tous les agents :
- No fabrication — n'invente pas de faits
- Acknowledges gaps — dit « je ne sais pas » lorsque c'est approprié
- Resists speculation — ne devine pas les informations manquantes
- No professional impersonation — ne se fait pas passer pour un avocat, un médecin, etc.
- Corrects false premises — signale les hypothèses incorrectes
- Blocks harmful content — refuse les demandes inappropriées

<Callout type="info">
  Les Platform Rules garantissent que tous les agents se comportent de manière fiable et sûre. Elles ne peuvent être ni désactivées ni modifiées.
</Callout>

## Onglet Knowledge Access

Contrôlez les documents auxquels votre agent peut accéder pour répondre aux requêtes.

### Modes d'Accès

| Mode | Comportement | Quand l'utiliser |
|------|----------|-------------|
| **Exclude Mode** | L'agent accède à TOUS les documents SAUF ceux sélectionnés | Masquer des documents sensibles tout en permettant l'accès au reste |
| **Include Mode** | L'agent accède UNIQUEMENT aux éléments sélectionnés | Restreindre l'agent à un ensemble spécifique de documents |

### Options de Sélection

Affinez l'accès grâce à plusieurs types de sélection :

- **Folders** — Sélectionnez des dossiers entiers et tous les documents qu'ils contiennent
- **Tags** — Filtrez les documents par tags assignés
- **Documents Individuels** — Incluez ou excluez des documents spécifiques au sein des dossiers sélectionnés

### Aperçu d'Accès

Le panneau d'aperçu montre l'accès effectif aux documents en fonction de vos sélections actuelles. Utilisez-le pour vérifier votre configuration avant d'enregistrer.

<Callout type="info">
  Commencez par **Exclude Mode** si vous voulez un accès large avec des restrictions spécifiques. Utilisez **Include Mode** lorsque vous avez besoin d'un contrôle strict sur les documents que l'agent peut consulter.
</Callout>

## Human Handoff

Activez le transfert vers un chat en direct afin que votre agent AI puisse transférer des conversations à une personne réelle lorsque les utilisateurs en font la demande.

**Comment l'activer :**

1. Dans l'onglet **Configuration**, faites défiler jusqu'à la section **Human Handoff**
2. Activez **Enable Human Handoff**
3. Configurez les messages :
   - **Handoff Message** — Affiché à l'utilisateur au début du transfert
   - **Accept Message** — Envoyé automatiquement quand un agent humain accepte la conversation
   - **Resolve Message** — Affiché lorsque l'agent humain met fin à la conversation
   - **Max Wait Time** — Expiration automatique si aucun agent n'accepte (5, 15, 30, 60 ou 120 minutes ; par défaut : 30 minutes)
4. Cliquez sur **Save Changes**

Lorsqu'un utilisateur demande à parler à une personne, l'AI crée une demande de handoff visible sur la page **Inbox**. Un membre de l'équipe l'accepte, discute avec l'utilisateur sur son canal, puis la résout une fois terminée.

<Callout type="info">
  Human Handoff est disponible dans tous les plans. Activez-le par agent dans l'onglet Configuration.
</Callout>

## Tester votre Agent

Avant d'enregistrer les modifications, vous pouvez tester votre agent :

1. Cliquez sur le bouton **Test Agent** en bas du formulaire
2. Le panneau du Playground s'ouvre
3. Menez une conversation de test avec votre agent
4. Fermez le Playground une fois terminé

<Callout type="info">
  Le bouton Test Agent est désactivé lorsque le statut de l'agent est Archived ou Inactive. Changez le statut en Active ou Testing pour activer les tests.
</Callout>

## Enregistrer les Modifications

| Bouton | Action |
|--------|--------|
| **Save Changes** | Enregistre toutes les modifications |
| **Test Agent** | Ouvre le Playground pour tester |

Pour abandonner les modifications, quittez la page via le bouton retour ou la navigation de la barre latérale.

**Ce qui est enregistré :**
- Seuls les champs modifiés sont mis à jour
- Vous verrez « No changes to save » si rien n'a été modifié
- Des messages de succès ou d'erreur s'affichent après l'enregistrement

**Gestion d'un Enregistrement Partiel :**
Si certaines modifications sont enregistrées mais d'autres échouent, les sections en échec vous seront indiquées et la page sera rechargée pour afficher l'état actuel.

<Callout type="info">
  Les modifications des paramètres de l'agent prennent effet immédiatement après l'enregistrement. Testez dans le Playground après chaque modification.
</Callout>
